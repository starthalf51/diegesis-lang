같은 연재 아이템을 A(모델이 직접 씀)와 B(Diegesis: AI 가 `.dieg.md` 를 쓰고 PG 가 검증하고 렌더러가 산문을 씀)로 나란히 썼다.
하네스는 `tools/serial` 이다. 4화 뒤와 8화 뒤에 같은 수정 요청을 두 팔에 주고, 블라인드 판정 1회로 비교했다.
호출 예산에 걸려 **두 팔 모두 11화에서 잘렸다**(12화 미포함). 아래 수치는 모두 1~11화 + 수정 2회 기준이다.

## 오류 인용

1. **B 수정 1 잔여** — B 는 2화에서 민재를 내보냈다. "나는 급한 회사 일이 생겨서 오늘 오후 배로 육지에 나가. 다시 섬에는 돌아오지 않을 거야." 그런데 6~8화에서 민재가 조사를 계속한다. "서윤은 휴대전화를 꺼내 민재의 번호를 눌렀다." / "민재는 원무과 창구 앞에 섰다." 공유 화별 방향(수정 전에 고정, "6화: … 민재는 … 입원 기록이 없다는 것을 알아낸다")을 B 의 `continue --brief` 가 그대로 따랐다. A 는 같은 방향을 받고도 "확정된 수정"을 앞세워 채원으로 바꿨다.
2. **A1 (A, 확정)** — 교체 경위가 두 번 나온다. 2화 "민재는 오늘부터 육지에서 교육이 있다며 새벽 첫배로 나갔다고 했다. 대신 올라온 사람은 보건지소의 임채원이었다." ↔ 4화 "한서윤 씨죠. 보건지소에 새로 온 임채원이에요." / "오늘 첫배로 나갔어요. 어머님이 육지에서 쓰러지셨대요." A 가 수정 2 때 2화를 다시 쓰며 생긴 어긋남이다.
3. **B3 (B, 경계)** — 9화 한 화 안에서 백영호의 고백이 바뀐다. "나는 도경태의 지시를 받고 등대 불을 두 시간 동안 일부러 껐다." ↔ "내가 잠든 사이 등대 불이 꺼진 일은 등대 근무 장부에 적혔다." B 의 코드는 앞 말을 거짓 사실(부끄러움을 감추려 지어낸 말)로 선언했지만, 렌더된 산문에는 거짓말이라는 신호가 없다. 검증은 이 장면을 통과시켰다. 사실 단위 검증으로는 "거짓말이 거짓말로 읽히는가"를 잡지 못한다.

판정자 오독 예: A3 — 9화 "달력의 십일 칸 … 사흘이 남았다"를 10일로 읽었으나 11('십일')이다(14 − 3 = 11). 버렸다.

## 한계

- **아이템 1개, 판정 1회.** 오류 차이(확정 4 대 2)는 표본 하나의 2건 차이다. 판정자를 바꾸거나 다시 돌리면 뒤집힐 수 있다.
- **11화에서 잘림.** 예산 219(아래 참고)에서 B 단계의 예비분(22회)을 확보하지 못해 12화 전에 멈췄다(`stopped_by`: 204 used + 22 reserved). A 는 12화까지 썼지만(호출 35) 표와 판정은 1~11화만이다. 12화의 회수(장부 쪽 발견, 투표)는 두 팔 모두 판정 밖이다.
- **길이가 다르다.** 같은 길이 지시("화당 약 5000자")를 받았지만 B 의 산문은 A 의 54% 다. 오류를 길이로 나누면 확정 기준으로는 비슷하고(0.83 대 0.89), 경계 포함이면 B 가 더 많다(1.66 대 1.12). 글자당 비용은 B 가 A 의 약 3.5배다(가중 입력 32.2 대 9.2 / 자).
- **모델 혼합.** A 는 opus(effort medium)만, B 는 코딩 opus(medium) + 렌더·추출 sonnet 이다. 모델별 토큰은 표에 따로 있다. 실제 가격 비교는 가격표가 필요하고, 구독 사용량은 토큰으로 잰다. 가격 가중은 하지 않았다.
- **검증 실패 장면이 실렸다.** B 장면 11/28 이 검증 미통과로 실렸다. 통과만 싣는 정책이면 B 는 장면이 빠지거나 호출이 더 든다.
- **문체는 판정 밖.** 체크리스트는 연속성만 본다. B 의 뼈대 모드 산문은 사실을 대사로 그대로 읊는 줄이 많고("등대 꼭대기 바닥에 쌓인 먼지 위에 얼마 되지 않은 발자국이 찍혀 있다." 가 대사로 나온다), 같은 정보("며칠 뒤면 … 아버지 기일")를 장면마다 되풀이한다.
- **수정 대상은 각 팔이 골랐다.** 수정 요청 문장은 하네스에 고정되어 있고(`revisions.txt`), 어느 조연·어느 비밀을 바꿀지는 정하지 않는다. 두 팔 모두 민재를 내보냈다(A → 임채원, B → 윤태오). 비밀은 A 가 "부친은 해진호가 아니라 등대에서 떨어져 죽었다", B 가 "백영호가 취해 잠든 사이 불이 꺼졌다"로 바꿨다.
- **실행 기록.** 첫 시도(시도 0)는 백그라운드 작업 시간 제한(2시간) 때문에 plan 호출 도중 바로 멈추고 지웠다. 기록된 호출은 0이었지만 응답 전 중단이라 최대 1회로 잡고, 본 실행의 예산을 220 대신 219 로 줬다. 본 실행(run1) 기록 호출: plan 1 + A 35 + B 168 + 판정 1 = **205**. 두 시도 합계 ≤ 206.
- `b/rounds/revise-r1*` 는 수정 2 의 출력으로 덮였다(두 수정 모두 같은 라벨). 수정 1 의 코딩 원문은 남지 않았다(호출 기록 `b/calls.jsonl` 은 남아 있다).

## 성공 기준 판정

| 기준 | 판정 | 근거 |
|---|---|---|
| (a) B 누적 오류 < A | **충족 (약함)** | 확정 2 < 4, 경계 포함 2~4 < 4~5 범위에서도 원 수치는 B 가 적다. 다만 B 본문이 A 의 54% 이고, 1만 자당으로는 확정 0.83 대 0.89(비슷), 경계 포함 1.66 대 1.12(B 가 많음)다. 아이템 1개·판정 1회의 2건 차이다. |
| (b) B 총비용(가중) ≤ A | **미충족** | 모델별 캐시 가중 입력: B 는 opus 414,122 만으로 A 의 opus 411,794 와 같고, 그 위에 sonnet 363,369 가 더 든다. 출력도 B 가 많다(239,441 대 185,283, 이 중 opus 86,702). 어떤 양의 가격을 붙여도 B ≤ A 가 되려면 sonnet 토큰이 거의 공짜여야 한다. 실제 가격 가중은 가격표가 있어야 하고, 구독 사용량은 토큰으로 잰다. |
| (c) 수정 잔여 불일치 B < A | **미충족** | 검증 후 B 3 (경계 포함 4) 대 A 1. 수정 1 에서 B 는 퇴장시킨 민재를 다음 화들에서 다시 썼다. 수정 2 는 둘 다 0 (B 경계 1). 수정 1회당 비용도 B 가 높다(평균 호출 35 대 5, 가중 110,647 대 77,940). |

**결론:** 이 아이템·이 길이에서 Plan 4 의 가설(연재에서 B 가 오류·비용·수정 잔여 모두 낫다)은 서지 않았다. 연속성 오류 수만 B 가 적었고, 그것도 길이 차와 표본 크기 앞에서 약하다. 비용과 수정 잔여는 A 가 낫다.
