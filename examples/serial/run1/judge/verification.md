# 판정 검증 (사람 대조)

판정 1회(`run1.txt`, 블라인드 X=B, Y=A, `mapping.txt`)의 지적과 수정 반영 표시를 원문과 하나씩 대조했다.
원문은 `prompt1.txt` 의 소설 X/Y 본문이다(판정자가 본 그대로). 두 팔에 같은 기준을 쓴다.

- **확정**: 인용이 원문에 있고, 지적한 모순이 원문만으로 성립한다.
- **경계**: 인용은 있으나 해석으로 설명될 여지가 있다(판정 규칙 "해석으로 설명되면 오류 아님", "확신 없으면 넣지 않음"). 본 수치에는 넣지 않고 범위로 따로 적는다.
- **거짓**: 원문을 잘못 읽었다. 버린다.

인용 18개는 모두 원문에 글자 그대로 있다(`quotes.md` 의 자동 대조 "있음").

## 수정 반영 일관성 (화별 표시)

## 원인 메모 (B 수정 1)

공유 `plan` 의 화별 방향은 수정 전에 한 번 쓰였고 "6화: … 민재는 그날 밤 육지 병원에 도경태의 입원 기록이 없다는 것을 알아낸다" 를 그대로 담고 있다. 두 팔 모두 이 방향을 받지만 **입력이 같지는 않다**. A 의 화 프롬프트에는 하네스 규칙 "요약의 `확정된 수정` 은 개요보다 우선한다"가 있다(`tools/serial/direct.go` aHead). 수정 때 요약 갱신 프롬프트는 요청을 요약 맨 위 `확정된 수정` 에 쌓는다. B 의 `dieg continue --brief` 에는 이런 우선 규칙이 없다(`tools/serial/b.go` runBEpisode). 그래서 B 는 옛 방향대로 민재를 다시 썼다. 다른 면도 있다. B 의 코드는 2화에 `fact minjae_leaves "… 섬에 돌아오지 않는다" true` 를 선언했는데, Diegesis 에는 떠난 인물이 계속 떠나 있는지 보는 검사가 없다. 이 잔여는 하네스의 비대칭과 Diegesis 의 빈틈이 겹친 결과다. 셈은 판정 그대로 B 3 이다. 참고(재채점 아님): 이 3개를 빼면 잔여는 B 1(수정 2) 대 A 1 이다.

## 판정자가 놓친 것 (세지 않음)

추가 지적은 하지 않았다(한쪽만 더 읽으면 비대칭이 된다). 참고로, B 의 4화는 수정 1 뒤 장면이 4개로 늘었고 열세 번째 칸의 새 못을 세 번 처음 보는 것처럼 발견한다. 셈에는 넣지 않았다.
