# 최소 수정 렌더(Arm M) — `dieg revise` 가 다시 렌더하는 대신 옛 산문을 고치면?

retcon 스파이크(`examples/value/retcon`, 커밋 daa3d62)에서 `dieg revise`(B)는 잔여 모순이 적었지만(A 4 대 B 0) 영향받는 장면을 처음부터 다시 렌더해 호출이 많고(B 84 대 A 15) 무관한 문장까지 바뀌었다(부수 변경 13,569자 대 1,250자). 이 스파이크는 렌더 단계만 바꿔 본다.

# 가설

영향받는 장면을 처음부터 렌더하지 않고, haiku 에게 **옛 산문 + 새 장면 명세 + 옛→새 명세의 정확한 차이**를 주고 "차이에 닿는 문장만 고치고 나머지는 한 글자도 바꾸지 말라"고 시키면, B 의 정확도(잔여 모순 0)를 유지하면서 부수 변경과 호출 수가 함께 준다.

사전 고정 기준 "최소 수정 효과 있음" = 아래 넷을 **모두** 충족:
1. 부수 변경 ≤ 전체 재렌더의 30%
2. 렌더+검증 호출 ≤ 전체 재렌더의 50%
3. 확정 잔여 + 새 모순 ≤ 전체 재렌더의 합
4. 카드 통과율이 낮지 않음

일부만 충족하면 "부분 효과", 아니면 "효과 없음".

# 방법

- **재사용:** retcon 스파이크 R1~R3 의 B 결과(개정 이야기 `rN/b/story`, 옛 산문 = run3 B 소설 `examples/serial/run3/b/novel`, 전체 재렌더 산문 `rN/b/novel`). 코딩 라운드는 다시 돌리지 않았다. 코드 쪽 비용(opus 2호출 `rev1-code-r1`/`fix-r2`)은 M·B 가 같고, 비교에서는 뺀 값과 포함한 값을 모두 적는다.
- **영향 장면 = 렌더 요청 해시가 바뀐 장면** (`dieg revise` 가 다시 렌더하는 바로 그 집합). 개정 이야기를 PG 에 적재해(`dieg load`) 장면 요청 JSON 을 `ir/` 에 저장하고, 옛 이야기(B 가 시작한 복사본)도 같은 방법으로 저장했다. 저장한 IR 로 계산한 렌더 해시가 두 쪽 모두 retcon 스파이크에 저장된 `.hash` 와 전부 일치함을 확인했다(옛 31/31, 새 R1 32/32·R2 32/32·R3 33/33). R1 10장면, R2 17장면, R3 7장면이 영향 장면이다.
- **차이(diff):** 장면 요청을 "항목: 내용" 줄(제목·장소·이전 줄거리·등장인물·행위·시점·시점 인물이 믿는 것·독자가 아는 것·말하면 안 되는 것·지시어)로 펴서 옛 쪽에만 있는 줄/새 쪽에만 있는 줄을 멀티셋 차집합으로 뽑는다(`sceneDiff`, 결정적). 바뀐 줄은 삭제+추가 한 쌍으로 나온다. 장면별 차이: `r*/diff/`.
- **프롬프트(스파이크 전용, 운영 프롬프트는 건드리지 않음):** 한국어 시스템 프롬프트(최소 수정 규칙 + 백엔드 `ko-haera` 의 목표 어투 문구를 `Backend.Prompt` 에서 그대로 가져옴) + 사용자 프롬프트(옛 산문, 새 장면 명세 = 운영 `Backend.Prompt` 의 사용자 부분, 변경 내역). 실제 프롬프트 전문: `r*/prompts/`.
- **호출:** 장면마다 haiku(effort low, 운영 렌더 기본값과 같음) 1회 → 운영 `render.ScoreCard`(기본값, tier2 absent-only, 모델 sonnet low)로 카드 검증 → 불통과면 카드 피드백을 붙여 1회 더 고치고 멈춤(이번 실행에서는 한 번도 필요하지 않았다). 라벨은 `render-sK-aN`/`extract-sK-aN` 로 dieg 와 같아 같은 비용 공식을 쓴다.
- **판정:** 재설정마다 sonnet 1회, retcon 스파이크와 같은 프롬프트(`rcJudgePrompt`)·방법. 입력은 M 의 고친 장면 + 손대지 않은 장면 + B 가 새로 만든 장면(아래 한계). 항목은 내가 원문과 대조해 확정/경계/기각으로 나눴다(`verification.md`).
- **측정:** 비용은 retcon 스파이크와 같은 공식(가중 입력 = 입력 + 0.1×캐시읽기 + 1.25×캐시쓰기; 가격 가중 = Σ 모델계수×(가중입력 + 5×출력), opus 1·sonnet 0.6·haiku 0.2). 부수 변경은 **retcon 스파이크의 코드 그대로**(`collateral()`, `editDist`, 사전 정한 키워드, 영향 단위 밖에서 바뀐 글자 수)이며 B 쪽 값도 같은 함수로 다시 계산해 스파이크의 값(2,796 / 6,814 / 3,959)이 재현됨을 확인했다.
- **절차:** `noclaude` 껍데기 아래에서 만들고 단위 시험·가짜 완성기 시험(`-me-dry`, 프롬프트 전문 확인)을 한 뒤, 껍데기를 빼고 한 프로세스(`serial minedit`)로 실행. 예산 가드는 호출 직전에 걸렸고 모든 호출이 `calls.jsonl` 에 있다. 플래그는 `-me-*` 라 기존 스파이크(`-rc-*`, 서브명령 `retcon`)와 겹치지 않는다.

# 중요한 사전 제약: 호출 상한 60 으로는 3개 재설정을 다 못 돌린다

영향 장면 34개(10+17+7)는 장면마다 편집 1회 + 카드 1~2회(B 도 같은 구조)라 최소 68호출 + 판정 3회가 든다. 상한은 60 이다. 그래서 **R1·R3 을 끝까지(판정 포함) 돌리고, 남은 예산으로 R2 는 앞 6장면만 시험(pilot, 판정 없음)** 했다. **R2 전체는 측정하지 못했다.** 합계와 판정은 R1+R3 기준이다. R3 의 새 장면(s32, s33)과 R1·R2 의 s32 는 옛 산문이 없어 편집 대상이 아니다. 두 팔 모두에서 이 장면들의 렌더 비용을 뺐다.

# 판정: **부분 효과**

| 기준 | 값 (R1+R3) | 충족 |
|---|---|---|
| 1. 부수 변경 ≤ 30% | 205 / 6,755 = **3.0%** (97% 감소) | 예 |
| 2. 렌더+검증 호출 ≤ 50% | 40 / 37 = **108%** | **아니오** |
| 3. 확정 잔여+새 모순 ≤ B | 0 ≤ 0 (판정자 항목 전부 세면 3 > 0) | 예 (확정 기준) |
| 4. 카드 통과율 낮지 않음 | 17/17 = 17/17 | 예 |

핵심: **부수 변경은 거의 사라졌지만(97% 감소) 호출도 토큰도 줄지 않았다.**
- 호출이 줄지 않는 이유: 호출의 거의 전부가 장면마다 1회씩인 편집/렌더 + 카드/추출이다. 영향 장면 수(17)가 같고 카드 검증을 똑같이 하므로 호출 수는 구조상 같다(M 40 대 B 37; M 쪽 카드 tier2 가 조금 더 걸렸다). 이 설계로는 50% 이하가 나올 수 없다. 호출을 줄이려면 영향 장면 수를 줄이거나(명세 차이가 문장 수준인 장면만 편집) 검증을 묶어야 한다.
- 토큰이 늘어난 이유: 입력에 옛 산문 + 변경 내역이 더해져 가중 입력이 약 1.8배(199,831 대 112,033). 출력은 "고친 산문 전체"를 다시 써서 줄지 않았다(69,253 대 65,731). 문장 단위 패치(바뀐 문장만 출력)로 바꾸면 출력이 줄 수 있으나 이번에 시험하지 않았다.
- 정확도는 유지됐다: 확정 잔여 0, 확정 새 모순 0. 카드는 첫 시도에 전부 통과했다.

## A 와의 비용 비교 (코드 비용 포함)

- R1+R3: M 460,663 / 44호출 대 A 511,159 / 12호출. **M 이 A 보다 가격 가중으로 0.90배**(B 는 0.84배). 단 R1 은 A 가 훨씬 싸고(M 1.78배) R3 에서만 M 이 싸다(0.58배; A 가 6개 화를 다시 썼다). 호출 수는 M 44 대 A 12 로 3.7배.
- **R2 포함 3개 전체는 측정하지 못했다.** pilot 의 장면당 비용(6,813)을 17장면에 곱하고 B 의 코드 비용 104,123 을 더한 외삽치는 약 22만, 3개 합 약 68만 대 A 597,774(약 1.14배). 즉 R2 를 넣으면 M 은 A 보다 비싸질 것으로 보이나 외삽이다.
- 즉 "B 가 이제 A 를 이기는가": 비용 총합으로는 R1+R3 에서 이겼지만 이는 R3 의 A 비용(372,985) 덕이고, M 의 렌더 쪽 절감 때문이 아니다(M 렌더+검증은 B 보다 오히려 21% 비쌌다). 재설정 하나당 지배 비용은 opus 코드 라운드(약 14만~15만)다.

# 호출 수

- **실호출 55 / 상한 60.** R1: 편집 10 + 카드 12 + 판정 1 = 23. R3: 편집 7 + 카드 11 + 판정 1 = 19. R2 pilot: 편집 6 + 카드 7 = 13. 전부 `calls.jsonl`(라벨 `rN-M-…`, 판정은 `rN-judge-M`). 실패한 호출 0(`err` 모두 비어 있음), 재시도 0.
- **낭비 0.** R2 pilot(13호출)은 판정에 쓰이지 않았지만 장면별 비교 자료로 쓴 측정이다. 남은 5호출은 쓰지 않았다.
- 시험(단위 시험, 가짜 완성기 전 구간 `-me-dry`)은 실호출 0. 모의 실행 출력은 저장소에 남기지 않았다.
- PG 적재: 이야기마다 한 번씩(옛 1 + 개정 3). 첫 시도에서 IR 파일 이름 오류로 옛 이야기 적재를 한 번 더 했다(옛 이야기 총 2회, 모델 호출 아님). 이후 적재는 `ir/` 캐시를 읽는다.

# 한계

- **R2 미측정.** 호출 상한 60 때문에 3개 중 2개만 판정했다(n = 2). R2 는 A 가 영향 화를 놓쳤던 재설정이라 가장 중요한 사례인데 M 판정이 없다. 기준 3 은 B 의 3개 합(0 잔여 + 1 새 모순, R2 에서 발생)이 아니라 R1+R3 의 합(0)과 비교했다.
- **판정은 1회·내 대조도 1명.** 판정자(sonnet 1회)가 지적한 3건은 모두 개정 IR 이 요구하는 문장이라 경계/기각으로 분류했다. 이 분류가 다르면 기준 3 이 깨져 "부분 효과"는 그대로이나 정확도 주장이 약해진다. 같은 문장이 B 산문에도 있는데 B 의 판정자는 지적하지 않았다는 점에서 판정 변동이 크다.
- **새 장면은 B 산문을 그대로 썼다.** R1·R2 의 s32, R3 의 s32·s33 은 옛 산문이 없어 편집할 수 없다. M 전문에는 B 가 렌더한 것을 그대로 넣었고, 이 장면들의 렌더 호출은 양쪽 비용에서 뺐다.
- **영향 장면 집합이 같다.** M 은 B 가 다시 렌더한 해시 변경 장면을 그대로 편집했다. 명세 차이가 "이전 줄거리"의 한 줄뿐인 장면도 포함돼 그런 장면은 편집 호출 없이 건너뛸 수도 있다. 그러면 호출은 줄겠지만 이번에는 시험하지 않았다.
- **편집이 "최소"인지는 부수 변경 정의에 의존한다.** 키워드 정의(사전 고정)로 센 값이다. 편집 거리는 글자 수준이라 문장 전체를 바꾸는 편집과 한 글자 수정을 구분하지 않는다.
- **카드는 사실 포함 여부만 본다.** 다시 쓴 문장이 어색하거나 어투가 흔들려도 통과한다. 어투·문체는 이번에 판정하지 않았다.
- **haiku 한 번씩.** 편집 품질의 분산은 측정하지 않았다(재현 1회).
- 이 스파이크는 12화 규모에서만 시험했다. 영향 장면이 많은 긴 연재에서는 부수 변경 절감이 더 클 수 있다.
